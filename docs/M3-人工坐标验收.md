# M3 人工验收

本轮只验收 Minecraft **26.1.2** 的新 Fabric 可视化编辑器。自动测试可以保证协议、YAML 事务和模板键名，但不能代替实际客户端的布局、拖拽和服务端 Display 预览检查。

## 安装

- 服务端：`paper/target/ArcMenu-0.1.0-SNAPSHOT.jar`
- 管理员客户端：从 [ArcMenu Editor](https://github.com/FENTAIIII/ArcMenu-Editor) 构建的 `ArcMenu-Editor-0.1.0-SNAPSHOT.jar`
- Fabric Loader 0.18.6
- Fabric API 0.155.2+26.1.2
- Java 25

本模组由 Java 编写，不需要 Fabric Language Kotlin。普通玩家不安装模组。管理员安装后彻底重新连接，再执行：

```text
/arcmenu edit example
```

## 布局检查

1. 中央窗口必须露出实时游戏画面，左侧是工具，右上是元素管理器，右下是属性，底部是模板。
2. 中央开口左上角显示的尺寸必须能分别被 16 和 9 整除。截图测量其可见内边界，宽高比应精确为 16:9；世界视角中心和菜单中心应位于该开口中央，不能落到右侧属性栏下。
3. 拖动左、右、下三条分隔线；各窗口不能互相穿透，中央窗口应保持 16:9。关闭再打开后尺寸应恢复。
4. 缩小窗口或更改 GUI 缩放，确认关键按钮和属性输入仍可操作。工具、元素、属性和模板列表应能各自在对应区域滚动。
5. 工具、元素状态、右键菜单和关闭按钮应全部显示为清晰的统一图标；“图像”文字后不得再出现缺字方框或未知字符。属性标签和输入值应在各自行内垂直居中，不能贴住上边缘。

## 前端和后端

1. 在前端 Tab 展开元素树，选择节点后检查属性字段与 YAML 一致。
2. 分别用组、矩形、边框、线段、文本、图像、物品和方块工具创建元素。选择组后创建时，新元素应进入该组；未选组时应进入根。
3. 展开图像工具，确认服务端所有图片路径都能滚动查看。点击候选后应创建 image 并写入所选 `source`。
4. 在中央窗口拖动根节点和旋转组内子节点，再拖动当前选框右下角手柄缩放。拖动时应是世界中的真实 Display 连续移动或缩放，不能只有客户端矩形变化，也不能因销毁重建整张菜单而闪烁；松开后最终位置与尺寸必须一致。一次手势会接受多次服务端修订，但只占一个撤销步骤；快速拖动不能使客户端选中另一个节点或写入旧修订。
5. 切换到后端 Tab，前端选择应清除。创建、移动并用右下角手柄缩放点击区域；它必须始终与画布横竖对齐。
6. 后端 Tab 不得出现组工具，不能把点击区域拖入模板窗口，前端组的旋转、隐藏或删除不得暗中修改后端。
7. 在元素管理器验证普通单选、`Ctrl+左键` 增减选择、`Shift+左键` 连续范围选择和 `Ctrl+A` 全选。右键菜单应对当前选择提供复制、粘贴、副本、编组、重命名和批量删除；禁用项不得执行。
8. 验证 `Ctrl+C/V/D/G`、`Ctrl+Shift+V`、`F2` 与 `Delete`。复制组时全部后代键名必须去重；批量选择同时包含组和其后代时只能复制或删除一次。把同层元素拖到另一行应调整 YAML 顺序，跨组拖动应明确拒绝而非静默改变变换。

## 属性、模板和文件

1. 对每类节点至少提交一个有效属性；再输入非法颜色、数值或 YAML 片段，确认服务端明确拒绝且正式预览保持上一个有效状态。
   数值字段应能横向拖动并实时改变真实 Display；一次连续拖动只占一个撤销步骤。单击进入文本输入，`Alt` 精细、`Shift` 加速、拖动中右键取消也要分别检查。
2. 在 `tooltip` 输入 `line one\nline two`，在 actions 输入有效多行动作 YAML，保存重开后语义应一致。
3. 把一个组拖入模板窗口，命名并保存。模板卡片应出现；把卡片拖回元素管理器后应复制整组；右键该卡片并选择“删除模板”，卡片和服务端对应 YAML 应一起消失。
4. 重复实例化同一模板，检查根与所有后代冲突键自动变为 `id2`、`id3` 等，菜单仍能解析。
5. 检查撤销和重做覆盖创建、删除、属性、拖动和模板实例化。`Delete` 删除选择，`Ctrl+S` 保存。
6. 首次保存后检查菜单旁存在 `.arcmenu-backup`，其内容是编辑前原稿；后续保存不能覆盖该备份。
7. 保存后检查 YAML 语义并重新打开。结构或属性编辑允许重新排版 YAML；发生问题时可用备份恢复。
8. 在外部编辑器修改磁盘文件后再保存，ArcMenu 必须拒绝覆盖。关闭后重新 `/arcmenu edit` 才读取外部版本。
9. “保存”后已有运行会话不变；“应用”通过全目录菜单和动画校验后，新会话才使用新版本。制造一个跨菜单或动画引用错误时，应用必须失败并保留原运行目录。

## 通过标准

以下项目全部通过后，M3 才能标记通过：

- 四类窗口、滚动、分隔线与布局持久化可用；
- 中央真实游戏窗口在不同窗口和 GUI 缩放下保持精确 16:9；
- 前端层级拖动正确，后端始终轴对齐；拖动过程更新现有真实 Display，服务端正式预览与选择一致；
- 服务端图片候选、所有工具和属性能形成有效菜单；
- 模板保存、实例化与全树键名去重正确；
- 撤销、保存、备份、外部冲突和应用保护没有损坏文档。

发现问题时请提供 Minecraft/Fabric/Fabric API 版本、窗口尺寸、GUI 缩放、编辑器 Tab、选中节点、操作步骤以及截图或短视频。
