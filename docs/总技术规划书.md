# ArcMenu 总技术规划书

版本：0.1 · 2026-08-31

本规划以用户最新审阅意见为准。阶段是交付与验收顺序，不是为了赶首版而永久删除功能。下文的目标能力与当前实现状态分开记录；代码进度见 README。

## 1. 产品目标与已经确认的边界

ArcMenu 专注菜单、菜单编辑与扩展 API，不内置微信、QQ 空间、商城业务，不制作独立 HUD 系统。普通玩家不安装模组；管理员使用 Fabric 编辑器。插件用展示实体向玩家呈现菜单，编辑器预览使用正式服务端渲染路径。

| 事项 | 已确认决定 |
| --- | --- |
| TrMenu | 高度还原使用习惯及适用功能行为，自行编写实现，不搬用其源码。逐项建立行为兼容表，不能用一个随意设计的小 DSL 冒充兼容 |
| 内容插件 | 只对接 CraftEngine，不实现 ItemsAdder、Oraxen、Nexo 适配 |
| 前后端 | 一个菜单 YAML 中的 `frontend` 与 `backend`，两个独立编辑器 Tab，不是同一画布中的混合元素树 |
| 分组 | 仅前端可以分组；后端点击区域是平铺集合，不可分组、不可绑定前端父组、不继承前端变换 |
| 点击区域 | 始终与菜单屏幕的横竖方向对齐，只能编辑位置、宽、高及交互逻辑；没有独立旋转、缩放、颜色或深度 |
| 动画 | 不提供整体/组透明度动画。动画中的 opacity 属性只允许文本节点；其他元素的静态透明度按渲染能力处理 |
| 长期动画 | 要能向通用节点动画扩展，不限于开屏动画；先做菜单过渡，再做变换轨道和文本动画 |
| 输入模式 | 触控模式优先，鼠标模式可以后续交付；输入边界必须现在隔离，不能以后向渲染器和菜单管理器到处插入判断 |
| 拖拽 | 尝试实现；构建出的模组必须由用户人工检查鼠标指向与服务端读取位置，未通过前不得称为已验收 |
| 支持范围 | Paper / Minecraft Java 1.21.1 至 26.2；Fabric 编辑器按客户端版本族提供构建，不能假设一个模组 JAR 通吃 |
| 性能与赞助 | 不故意削弱免费版。性能优化可以是付费收益点；对免费版严重不友好或显著影响基础使用的单项优化应开放 |
| 扩展 | Java 友好的 API，统一菜单/附属应用路由；完整试穿等业务通过独立扩展逐步支持 |

`fontend` 是笔误，只使用 `frontend`。不保留 `[consol]` 等错误拼写兼容别名。

## 2. 版本与构建策略

### 2.1 服务端

- 公共模型与基础插件输出 Java 21 字节码，基线依赖 Paper 1.21.1 API。
- Paper 1.21.x 在 Java 21 环境验收；26.1+ 在 Java 25 环境验收。旧字节码能被新 JVM 加载，不等于 API、资源包和协议自动兼容。
- 常规逻辑优先使用跨版本 Bukkit/Paper 公共 API。确有差异的包结构、客户端能力、模型和网络处理放入版本适配边界，不散布到业务代码中。
- 若跨版本公共 API 无法覆盖某项能力，以适配实现和明确能力表解决，不能把某个版本的异常悄悄吞掉。
- 暂不承诺 Folia；用户要求的发行范围是 Paper。未来支持 Folia 必须另行验收线程与调度规则。
- 生产构建锁定稳定 Kotlin 版本；将空壳中的 2.4.20-RC2 替换为已经发布的 2.4.10。保留 Maven，不为插件部分无故切换构建系统。

### 2.2 管理员模组

- Fabric 构建使用 Loom，按 Minecraft API 变化划分适配源码与发行包。
- 共享协议和文档语义；Screen、输入事件、网络 payload 注册、世界画面投影等属于客户端版本适配。
- 最早的坐标探针只需先在一个明确版本跑通，再扩展版本矩阵；不能把一个版本的成功推广为整个范围支持。
- UI 显示协议版本、当前客户端/服务端版本、预览修订号和坐标诊断值。

### 2.3 兼容验收矩阵

至少覆盖 1.21.1、1.21.4、1.21.5/1.21.6、1.21.8、1.21.11、26.1.x、26.2 的关键变化点；发行前补齐声明支持的各正式版本。每个目标记录：Java、Paper 构建、Fabric 构建、CE 版本、包格式、启动/交互/清理/资源加载/编辑验证结果。

编译通过、无客户端启动测试、原版客户端交互验收、用户拖拽验收，是四种不同状态。任何版本不得仅凭范围比较函数或编译成功标成“已支持”。

## 3. 代码与职责边界

开始只创建已有实际职责的模块，不创建空扩展框架。

| 模块/边界 | 职责 | 不允许依赖 |
| --- | --- | --- |
| core | 文档模型、校验、前端层级变换、平面坐标、后端命中、动画数据和调度语义 | Bukkit Player/Entity、Fabric 类 |
| paper | 命令、会话、生命周期、输入采样、展示实体实现、服务端线程调度 | Fabric 客户端类 |
| 行为执行边界 | TrMenu 风格解析与执行、条件、状态、路由、占位符桥接 | 具体图形实体实现 |
| 资源边界 | 图片索引、专用字体、资源包生成、CE 事件桥接 | 编辑器 Screen |
| 编辑服务 | 草稿、操作校验、修订号、保存/应用、预览会话、协议 | 客户端 UI 控件 |
| Fabric editor | 两个编辑器、本地鼠标与手柄、属性面板、撤销栈、协议适配 | 服务端 Bukkit 对象 |

输入形成统一的菜单坐标样本与点击事件。触控模式适配器只负责从玩家眼睛射线求得样本；鼠标模式适配器输出同样的数据。命中、tooltip、动作路由不判断输入来自哪一种模式。

渲染逻辑只接收已编译的可视节点与状态，不自行解析 YAML、执行命令或处理玩家输入。会话拥有实体、订阅和任务，关闭时统一释放。

第一条可运行渲染路径使用私有、非持久化 Bukkit Display 实体，作为跨版本基准。数据包虚拟实体列为后续对比候选，必须比较客户端 FPS、带宽、MSPT 和生命周期成本，再选择正式策略；不预先宣称虚拟实体一定更快。

## 4. 文档、坐标与前后端编辑器

### 4.1 菜单文档

每个菜单一个文件，目录 `menus/`。文件含 `schema-version`、`id`、`canvas`、`frontend`、`backend`，后续按已定义语义增加 events 等域。字段校验要报告文件、元素和属性路径，错误配置不得替换正在使用的有效菜单。

- 元素 ID 在一个菜单内唯一，包括所有前端后代和后端点击区域。
- 前端为树，组的 children 是子元素映射。叶节点与组都具有稳定 ID。
- 后端为平铺映射，禁止 `children`、`parent`、`group`、`rotation`、`scale` 等变换关系。
- 组名称变化与重排不改变 ID；复制前端子树时生成新的 ID。
- 严格区分未实现能力与拼写错误，不能把不认识的类型悄悄变成矩形或忽略。
- 模组写配置时必须保留未编辑业务字段。注释、锚点和逐字格式保留需另行验证；无法安全编辑的结构显示只读提示，不静默删除。

### 4.2 坐标规则

- 菜单使用逻辑画布单位，默认画布宽 320、高 180；原点在中心，X 向右、Y 向上。
- 前端元素 offset 与后端 x/y 均表示中心位置。后端命中范围为中心加减宽高的一半。
- 画布与世界单位通过 pixels-per-block 映射；这不是承诺逻辑单位等于玩家显示器像素。
- Z 为垂直菜单平面的深度，朝观察者为正；仅前端可配置。
- 前端旋转属性在文档和 UI 中按 Z、X、Y 排列，Z 为平面内旋转；组合矩阵顺序固定并测试，不依赖字段书写顺序。
- 前端子组使用 parent × local 组合变换。沿用 libs-arc-ui 的父层级作用于全部后代的含义，但统一到一个菜单文件中。
- 后端只在菜单基础平面上求交，与前端组矩阵完全无关。两者共用基础画布映射，不共用前端层级。
- 重叠点击区域按显式 priority 优先，再按文档顺序确定同级结果。可视装饰不自动阻挡后端点击。

### 4.3 两个编辑器

管理员客户端采用四类可停靠工作窗口：工具、元素管理器、模板和属性。执行 edit 时，服务端强制为编辑会话建立鼠标模式固定摄像机并正对正式菜单，客户端系统鼠标负责编辑交互。侧栏与底栏围绕中央真实游戏窗口，窗口固定为精确 16:9；客户端按该比例建立相机投影，在世界与后处理渲染完成后复制完整真实帧并缩放合成到窗口内，随后绘制全不透明 dock。不能只用面板遮挡全屏画面或只修改会被渲染通道覆盖的 OpenGL viewport。窗口尺寸属于客户端偏好，菜单内容仍由服务端草稿权威管理。

前端 Tab 提供图层树、锁定、隐藏、分组、拆组、重排、复制粘贴、撤销重做、属性编辑、平面拖动、缩放手柄与模板。

后端 Tab 只提供平铺点击区域列表及矩形位置/尺寸、tooltip、动作条件编辑。未选中半透明蓝色，选中半透明红色；洋葱皮按钮仅切换编辑覆盖层，不修改菜单颜色或运行时可见性。后端多选、复制、对齐可以作为批量操作，但绝不创建组或父子关系。

切换 Tab 清除另一编辑器的选择与拖拽状态。前端删除/旋转/隐藏/分组不会自动修改后端。编辑器可以显示前端作为定位参考，但不能因此允许在后端 Tab 编辑前端。

前端组模板保存视觉子树及资产依赖，不自动捆绑后端按钮。需要复制整个菜单时使用菜单级复制，不能借“模板”引入用户明确禁止的点击区域分组。模板插入先采用副本语义，不提供隐含的实时链接更新。

## 5. 图形与资源

基础类型：line、frame、rectangle、text、image、item、block、group。编辑器可以把 item/block/CE 展示上下文组织成用户所说的“物品工具”和“模型工具”，内部保留明确类型。

- line 用一个矩形图元，frame 用四个线段。尺寸、颜色、静态透明度按类型定义。
- text 支持内容、字号、换行宽度、对齐、颜色、静态透明度、字体；不把 TextDisplay 的裁剪范围误当作文字几何尺寸。
- image 使用图片逻辑路径、固有比例、缩放与静态透明度；不把物理文件路径直接暴露给客户端。
- item 使用原版或 CE ItemStack，并指定 GUI/HEAD/手持等展示上下文。block 使用方块状态或已验证的 CE 展示方式。
- group 没有颜色、文字内容或 opacity，不对应一份业务状态，也不创建可交互实体。
- 复杂轮廓优先图片，避免用大量实体模拟网格；编译后可显示图元成本。
- 物品展示上下文不是完整装备试穿。全身模型、盔甲 renderer 和试穿属于后续扩展。

资源目录：`images/`、`templates/`、`menus/`、`animations.yml`、`tooltip.yml`。使用 `animations.yml` 作为单一正式文件名，不同时引入 anime/animation 等别名。

`/ui/logo.png` 在配置中是 images 虚拟根下的路径，不能被当作磁盘绝对路径。禁止越出虚拟根。使用 `arcmenu:*` 专用字体，不修改 `minecraft:default`；专用字体是兼容隔离，不是保密或防提取机制。

图片到字体字符的分配在一次已应用资源版本内保持一致；菜单编译必须绑定该资源版本。新 PNG 和字体变化需要重建资源包并等待客户端加载；动态 update 只能在已有资源中切换，不在每次刷新时打包。

CE 桥接接入其资源包构建事件，加入 ArcMenu 输出，明确启动/重载顺序、失败反馈与已加载客户端状态。CE 模式下只有 CE 负责向玩家发送最终包。无 CE 时基础原版菜单仍可用，并提供资源包导出；不额外实现 HTTP 托管服务。

## 6. TrMenu 行为还原策略

目标是高度还原适用场景的用户体验，而不是换个名字的自定义动作引擎。参考基线是 TrMenu v3 的公开文档、公开配置示例及用户后续提供的实际菜单；不得搬用上游实现代码。

建立 fixtures 与兼容表，每项注明：原语法、触发顺序、条件与否定分支、返回/取消范围、占位符展开时机、ArcMenu 差异及测试。不同历史版本存在差异时记录采用的基线，不自行拼接成未声明方言。

| 行为族 | 目标 |
| --- | --- |
| 动作入口 | 尽量还原标量、列表、条件动作组、priority、actions/deny 分支的既有习惯 |
| 点击 | all、left、right、shift 等可获得的输入类型；按上游基线确定 all 与具体点击的执行顺序 |
| 常用动作 | tell、command、console、sound、open、close、refresh、return 与菜单返回路由 |
| 条件 | 优先权限、比较、布尔组合与常用 smart condition；扩展 Kether/脚本兼容时通过独立执行后端接入 |
| 高级状态 | 参数、meta/data、条件分支、延时与任务、输入捕获按阶段还原 |
| 原版专有域 | slot、背包拖动物品、容器布局等不生搬硬套；明确标为不适用 |
| update | ArcMenu 使用单一 tick 间隔，缺省 -1；不继承 Material/Name/Lore/Slot 四元素数组 |

不能把所有 TrMenu 大小写或正式别名一律当作错误；高度还原需要保留经确认的上游习惯。但文档统一推荐规范写法，不引入 CRServer 私有错误拼写，也不沿用 `[openmenu]` 作为主要语法。

显示刷新、显示条件、可用条件和执行条件分别确定时机。`update: -1` 仅关闭周期刷新，不能关闭初次求值、显式 refresh、API 更新或动作前权限重验。动作执行绑定当前玩家与会话，旧会话的延时任务不得错误作用到新菜单。

预览模式默认不执行动作。进入交互测试必须明确切换状态，并按照真实权限执行；交易等副作用不能由美术选择操作触发。

## 7. 动画引擎路线

不是“不做动画”，而是先明确可支持的属性与运行时成本。

### 7.1 第一阶段：菜单过渡

支持进入、退出、菜单切换的位移与缩放，采用有限持续时间和缓动。过渡作用于前端可视根；后端点击区域始终在基础菜单平面，不变形，过渡期间停用业务点击。进入完成后视觉根回到配置姿态；关闭完成后销毁会话。

不接受菜单根或组的 opacity 轨道。配置了禁止属性时报告明确错误，不静默忽略，也不只淡出某一部分后冒充整体效果。

### 7.2 第二阶段：节点轨道

以 target（元素 ID）、property、keyframes、duration、easing、loop、trigger 表达轨道。支持前端节点的平移、旋转、缩放，文字内容帧与文本 opacity；image/item/block/group 不提供 opacity 动画。轨道不直接执行命令，不使用 update 字段伪装时间线。

同一节点同一属性同时只能有一个明确所有者；规定替换/排队/取消语义，菜单关闭统一停止。矩阵关键帧尽量利用客户端插值，但不能据此声称任意动态节点可精确点击。后端区域不随前端动画移动，这正是已确认的前后端分离规则。

持续旋转模型是轨道能力的验收例；无需引入任意脚本求值或完整视频时间线。高级服务端 API 可显式更新前端状态，但不得绕过统一调度和清理规则。

## 8. 触控模式、鼠标模式与 tooltip

触控模式适配器将眼睛射线投射到菜单平面。只对打开菜单的玩家采样；只在指针/命中变化时更新 hover 和 tooltip，不重新渲染整个菜单。

鼠标模式作为独立 PointerSource，负责输入解释、相机策略和指针图形。配置支持强制模式/玩家选择/默认值；设置服务属于 ArcMenu，不依赖 CRServer 的手机 app。

`offset.yml` 为触控模式与鼠标模式分别提供全局 distance 和屏幕局部 x/y/z 整体偏移。运行层按距离同比缩放真实宽高，以保持画面的视角尺寸、逻辑坐标和 backend 命中一致；编辑器使用鼠标模式，因此直接继承 mouse 段，不增加专用配置。

正式接入前验证 FOV、分辨率、宽高比、视角变化、移动、延迟、点击采样时机与恢复相机。普通玩家没有模组时，不能承诺获取任意客户端键盘或真系统鼠标事件。触控模式的本地视线响应不意味着 tooltip 和动作没有网络延迟。

tooltip.yml 以 `touch` / `mouse` 两段为触控模式与鼠标模式分别配置相对偏移和可选九宫格皮肤，后端节点配置 tooltip 内容与可选 update。普通文本/背景不依赖资源包；可选皮肤从 ArcMenu images 读取 background/frame，构建时合成九个切片，运行时按展开后的文字自动调整宽高，并提供皮肤/文字独立位移、四边 padding、宽高补偿、缩放、接缝及逐行逐列微调。CE 的物品 tooltip_style 不会由 ItemDisplay 直接触发；黄玉外观通过这条独立适配路径使用服务器管理员提供的 CE 默认资源。屏幕边界处理仍待补充。

## 9. 编辑协议与人工坐标验收

使用自有命名空间 Plugin Message / CustomPayload，不借用 BungeeCord 转发通道。服务端校验编辑权限、操作类型、目标文档、修订号与数据范围；客户端提交的是编辑意图，最终文档由服务端校验后确认。

最小协议包含握手、文档快照、选择、属性补丁、拖动事务、撤销/重做、保存、应用、错误与坐标探针。为大文档根据目标版本消息上限分块，限制消息大小与频率；不无界接受任意文件写入或任意动作执行请求。

一个菜单先允许一个写入者，不制作多人 OT/CRDT。拖动采样限频发送并逐次更新服务端真实 Display，同一手势的多次服务端修订合并成一个撤销事务；发送频率与客户端绘制帧率解耦。ACK 携带服务端采用的坐标与修订号，客户端不能把未确认值当作已经应用。

编辑态分为草稿预览、保存、应用。草稿只给编辑者；无效草稿不替换运行版本。恢复/切菜单/断线时结束未完成拖动，不让迟到的补丁写入另一个菜单。

### 用户必须参与的拖拽验收

构建可安装的模组和匹配插件，提供明确的坐标探针页面及菜单。客户端显示鼠标像素、逻辑画布坐标；服务端回传独立计算/采纳的坐标、命中 ID、修订号，并在正式预览平面显示位置标记。

用户需要人工检查：中心、四角、不同 FOV/宽高比/GUI 缩放；前端旋转/缩放组中的拖动；后端轴对齐矩形的移动/缩放；切 Tab；模拟高延迟；撤销重做与保存后重开。

自动测试可以检查投影往返、消息序列、非法操作和事务，但不能代替用户确认“鼠标点的位置就是插件读取的位置”。人工未通过时，拖拽仍为待验收；不得对外发布为已验证功能，也不得用客户端自己回显自己的坐标当作服务端正确性的证据。

## 10. 生命周期、性能与赞助优化

- 菜单定义只在加载/编辑应用时解析，静态节点只在变化时更新。
- 每玩家会话持有可视句柄和小量动态状态，不为每个静态节点创建一个 Bukkit 定时任务。
- 带周期的内容统一调度，值未改变时不发送重复元数据；无周期内容不反复求占位符。
- Bukkit/玩家/实体操作在正确服务端线程执行；图片处理与包构建可以异步，发布结果必须回到受控边界。
- 关闭、退出、死亡、传送、切世界、插件禁用、预览结束均释放会话资源。显示实体非持久化、默认不向其他玩家可见。
- 热重载先完整校验，再替换定义；失败保留旧版本，不能先销毁正在使用的有效菜单。
- 只处理本插件拥有的实体，不清理其他插件展示实体或运行服务器目录。

验收使用同一菜单、同时打开人数和更新频率，分别记录首次打开 bytes、静态 bytes/s、动态 bytes/s、MSPT 增量、客户端 FPS、内存/任务/会话/实体回落。先用 20/100/300 个图元、1/10/50 个同时打开会话建立基线，之后用用户真实菜单修订。上述是测试负载，不是默认限额，也不是性能承诺。

赞助优化必须有可复现的收益和真实实现差异，不通过固定延迟、限制刷新率或禁用必要缓存人为制造免费版劣势。内存泄漏、资源无法回收、静态菜单无意义重算、重复发包等基础问题的修复属于开放核心。昂贵且可选的进一步优化可保留赞助收益；若某一项对开源用户严重不友好，单独开放该项。

美术/模板/附属插件和优化代码的发行边界分别管理，不分叉两份菜单语义。不开启混淆、DRM 或传播保护。具体许可证在正式发布时确定，不未经用户决定套用上游许可证。

## 11. 实施阶段与完成标准

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| M1 文档与渲染基线 | core/paper 模块、严格菜单校验、前端分组/图元、平铺后端命中、私有只读预览、坐标诊断、测试 | 可构建 JAR；配置和几何测试通过；无效重载不丢旧定义；预览不执行业务动作。暂不冒充完整可交互菜单 |
| M2 运行菜单 | TrMenu 行为兼容表及 fixtures、常用动作/条件/路由、动态文本、普通 tooltip、会话清理 | 与对应 TrMenu 示例的适用行为对照验收，拒绝未支持语法且错误可定位 |
| M3 编辑器坐标闭环 | Fabric 四窗口工作区、精确 16:9 真实游戏 viewport、两个 Tab、服务端图片、组模板、属性、读写草稿、拖拽/撤销、正式预览 | 交付匹配 JAR，由用户人工确认布局、坐标、模板往返、保存保护与命中；未通过则继续修正 |
| M4 资源与完整创作 | 图片构建、CE 合包/物品模型、模板、图层操作、保存/应用保护 | 新增/删除/替换资源、包加载失败、重载、前后端分离都可验收 |
| M5 动画与 API | 菜单过渡、文本动画、逐节点变换轨道、Java 扩展接口 | 拒绝禁用 opacity；关闭取消动画；示例附属应用通过公共 API 路由 |
| M6 版本与体验 | 1.21.1–26.2 版本矩阵、鼠标模式原型、性能对比、赞助优化划分 | 逐版本标注实际结果；鼠标模式不侵入现有业务；性能收益有基线 |
| 后续扩展 | 完整试穿、复杂附属业务、更高级作者工具 | 独立需求与独立验收，不默认塞入核心 |

M3 的坐标验证应在 M2 开发过程中尽早插入，不等所有高级逻辑完成才发现输入问题。用户不急于首版，阶段优先级服从正确性与人工反馈；不能为赶阶段宣称未完成兼容。
