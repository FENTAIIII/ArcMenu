# M6 版本与体验

M6 包含三个相互分离的交付：普通玩家运行菜单的鼠标模式原型、版本编译矩阵、性能测量与赞助优化边界。之后重做的 M3 管理员编辑器是独立 Fabric 客户端；它不把客户端输入策略写进运行菜单的命中、tooltip、actions 或动画引擎。

## 触控模式与鼠标模式

触控模式和鼠标模式都通过 `PointerController` 输出同一种菜单逻辑坐标。`MenuSessions`、`HitTester`、tooltip 和动作执行器不判断坐标来自哪种模式。菜单路由继续复用第一次打开的世界平面，鼠标坐标在 open/back/附属路由切换时保留并按新画布边界夹取。

普通玩家不安装模组，服务端必须安装 ProtocolLib 5.4。进入鼠标模式时，ArcMenu 在首次菜单平面的观察点创建固定、不可见、仅该玩家可见的空 `TextDisplay` 摄像机实体。它不是 LivingEntity，因此没有分离的 head/body yaw 或姿态眼高；实体位置就是摄像机位置，唯一的 yaw/pitch 由平面法线计算，正对菜单中心。随后发送 camera 包让客户端从该实体渲染。菜单路由继续复用同一平面和摄像机，因此 open/back 不切屏。

实体生成/相对旋转包用一个字节表示角度，每档 `1.40625°`；新版本的完整实体位置同步包则直接携带浮点 yaw。鼠标模式建立平面时先按 byte 包规则量化玩家 yaw，并把同一个可编码角度原样写进摄像机实体。这样生成包、相对旋转包和完整位置同步包最终都与菜单平面一致。不能把实体 yaw 放在量化区间中心，否则完整位置同步会保留半档偏差。触控模式不使用实体摄像机，仍保留玩家原始浮点 yaw。

ProtocolLib 在 [`ServerboundMovePlayerPacket.Rot`](https://mappings.dev/1.21.6/net/minecraft/network/protocol/game/ServerboundMovePlayerPacket$Rot.html) 与 [`PosRot`](https://mappings.dev/1.21.6/net/minecraft/network/protocol/game/ServerboundMovePlayerPacket$PosRot.html) 到达游戏逻辑前读取 yaw/pitch，相邻样本差值累积为鼠标坐标；旋转包和纯位置包在鼠标模式活动期间被消费，所以隐藏玩家不会改变服务端位置或朝向。摄像机通过 [`ClientboundSetCameraPacket`](https://mappings.dev/1.21.6/net/minecraft/network/protocol/game/ClientboundSetCameraPacket.html) 设为客户端渲染目标，客户端本地玩家怎样旋转都不会移动画面。首次进入时先以第 0 帧生成完整菜单和捕获面，再发送摄像机实体、切换摄像机、客户端旁观者状态和带编号的旋转同步；摄像机切换必须排在旁观者状态之前，避免客户端从玩家本体渲染一帧无碰撞视角。只有客户端确认这次旋转同步后，时间轴、鼠标输入和第三方应用 tick 才开始。菜单间切换复用已确认的摄像机，不重复进入握手。pitch 接近 ±85° 时，ArcMenu 在摄像机背后把隐藏玩家单次重置到进入时朝向，等待客户端确认后的第一个样本不计入鼠标移动。

鼠标模式的指针是独立、私有、非持久化 TextDisplay。代码固定解析 `images/mouse/mouse.png` 与 `images/mouse/choose.png`（资源虚拟路径 `/mouse/mouse.png`、`/mouse/choose.png`），使用普通不透明文字渲染路径；悬停在当前可交互的 backend 区域时切换为 `choose.png`，移出或进入不可交互的菜单过渡时恢复 `mouse.png`。两张 20×30 PNG 保持纵横比，PNG 左上角的箭头尖端对齐服务端命中坐标。鼠标模式与触控模式都接收右键主操作；服务端只用指针坐标命中固定 backend 矩形。

Tooltip 的 TextDisplay 使用正常深度测试，不能启用 `see_through`；否则它的半透明背景会成为可透视水体和后方地形的窗口。背景透明度仍由 `tooltip.yml` 的 `background: '#AARRGGBB'` 明确控制。

`offset.yml` 分别定义触控模式和鼠标模式的全局屏幕位置。两者的默认距离都是 `0.65` 格；改变距离时仍保持 `pixels-per-block * distance` 不变，因此视角大小、逻辑画布与 backend 命中坐标不变。每段的 `offset.x/y/z` 以屏幕局部坐标、世界格为单位整体移动菜单、命中平面和捕获实体。编辑器通过鼠标模式打开，所以自然使用 `mouse` 段，不存在编辑器专用偏移。

运行菜单不会因为移动、距离、权限变化、传送、死亡或切换世界自行退出。传送和重生后仅重建世界实体与摄像机，保留当前菜单、光标、路由和动画状态，不运行菜单 close/open 事件。退出只来自显式关闭指令、菜单交互配置的 `close` 动作、退出服务器或插件停用。客户端本地玩家可能在移动包被服务端消费期间产生位置预测，因此关闭时保持固定摄像机，先把客户端玩家绝对同步回服务端坐标，再恢复真实游戏模式，并用第二次绝对同步作为有编号的确认屏障；收到确认后才把 camera 目标切回玩家并移除摄像机。若客户端未确认，一秒后执行保底交还。退出服务器时直接丢弃私有状态，不等待已断开的客户端。

菜单入口只使用下面这一套根字段，不接受别名：

```yaml
open-commands:
  - arc
main-menu: true
```

`open-commands` 中每一项都是不带 `/` 的完整根命令名；命令后的参数会作为菜单参数传入。所有菜单合计必须有且仅有一个 `main-menu: true`，自定义命令名也不能重复或覆盖服务器已有命令。加载和 `/arcmenu reload` 会先验证完整入口集合，再原子替换动态命令；失败时旧菜单与旧命令继续可用。玩家潜行并按 F 时，若已经打开任意 ArcMenu 菜单或应用则关闭它，否则打开唯一主菜单；事件被接管后不会交换副手物品。`config.yml` 的 `shortcuts.shift-f` 可整体关闭这一快捷键；关闭后 ArcMenu 不监听其开关菜单语义，也不取消原版换副手动作。

原版系统准星仍可能显示，摄像机包、素材热点以及第三方协议/反作弊插件的组合必须实机验证。M6 在用户人工确认之前仍是候选。

`offset.yml`：

```yaml
touch:
  distance: 0.65
  offset: { x: 0.0, y: 0.0, z: 0.0 }

mouse:
  distance: 0.65
  offset: { x: 0.0, y: 0.0, z: 0.0 }
```

`config.yml`：

```yaml
shortcuts:
  shift-f: true              # false 时完全不接管 Shift+F

mouse:
  policy: player-choice       # player-choice / force-touch / force-mouse
  default: touch              # 仅 player-choice 的无偏好玩家使用
  cursor:
    sensitivity-x: 2.0        # 每度 yaw 对应的菜单逻辑单位
    sensitivity-y: 2.0        # 每度 pitch 对应的菜单逻辑单位
    clamp-margin: 3.0
    size: 5.0                # 全屏画布下固定 mouse.png 的逻辑高度
    z: 5.0
```

玩家命令：

```text
/arcmenu mode
/arcmenu mode mouse
/arcmenu mode touch
```

`player-choice` 会把偏好写入玩家 PDC。强制策略会拒绝相反选择。修改配置后执行 `/arcmenu reload`；候选配置无效时保留当前输入与运行屏幕设置。旧 `force-crosshair/force-cursor`、`crosshair/cursor` 配置值及 `/arcmenu mouse` 命令继续作为兼容别名。`tooltip.yml` 内部的 `cursor` 与 `crosshair` 是两个独立样式段。

Java API 新增 `pointerMode`、`setPointerMode` 和 `pointerPolicy`，枚举位于 `com.fentai.arcmenu.api`。这样附属设置菜单可以更改 ArcMenu 自己持有的玩家偏好，不依赖 CRServer 的业务 app。

## 性能测量

`/arcmenu performance` 是逻辑工作计数器，不是网络抓包器。它报告：

- 活动 ticker 的采样数、平均和最大执行微秒；
- 实际提交与因值未变化而抑制的 Display 矩阵更新；
- 实际提交与抑制的动态文字、透明度和图片元数据更新；
- 计数窗口内新建实体数，以及当前会话/实体数。

用 `/arcmenu performance reset` 开始固定窗口。Paper 公共 API 无法给出这些实体元数据的真实网络 bytes，也不能测客户端 FPS，因此命令会明确提示 bytes、整体 MSPT、内存和 FPS 需要 spark/协议抓包/客户端采样，不能用逻辑写入数冒充。

`scripts/New-PerformanceMenu.ps1` 可生成 20、100 或 300 个静态 rectangle 的负载菜单，例如：

```powershell
./scripts/New-PerformanceMenu.ps1 -Nodes 100 -Output 'C:/path/to/plugins/ArcMenu/menus/perf-100.yml'
```

固定比较流程：同一服务端/JVM/视距/FOV/菜单，分别让 1、10、50 个会话打开 20、100、300 节点菜单；预热后重置窗口并采样 60 秒。记录首次打开 bytes、静态 bytes/s、动态 bytes/s、MSPT 增量、客户端 FPS、堆内存、任务/会话/实体关闭回落。这里的数量是测试负载，不是默认限额或性能承诺。

`benchmarks` 模块提供 core-only 的 `CorePerformanceBaseline`。它在独立 JVM 内对 SceneCompiler 和 AnimationTimeline 做微基准，用于比较同一机器上代码变更前后趋势；它不包含 Bukkit、网络、客户端或真实玩家，因此不能替代上述测试。

2026-09-01 在 Java 25.0.2 HotSpot 上以每种负载独立 JVM 执行的初始基线如下。数值是单次 core 操作微秒，供同机回归比较：

| 静态节点 | SceneCompiler median | SceneCompiler p95 | 单轨 Timeline median | 单轨 Timeline p95 |
| ---: | ---: | ---: | ---: | ---: |
| 20 | 4.121 µs | 8.333 µs | 0.247 µs | 0.707 µs |
| 100 | 10.742 µs | 17.973 µs | 0.248 µs | 0.462 µs |
| 300 | 35.396 µs | 41.387 µs | 0.204 µs | 0.487 µs |

这是当前代码的起始点，不是 TPS 或可承载玩家数承诺。Timeline 用单条轨道，节点数不会改变它的工作量，因此该列只用于观察测量噪声和时间线回归。

## 开放核心与赞助优化

当前没有把任何已实现性能修复放入闭源层。以下能力属于开放核心，免费版必须保留：

- 统一 ticker、静态节点不周期求值、占位符值不变不发元数据；
- 单实体矩阵相同则不重启插值，动画不每帧创建实体；
- 资源索引/cache、失败原子回退、完整生命周期清理；
- 指针控制器边界、基础模式选择和准确的服务端命中；
- 性能计数与可复现负载，避免靠隐藏数据制造优化说法。

可以作为赞助收益候选、但尚未据此锁定代码的项目：版本专属的批量包编码器、更昂贵的场景 diff/预计算实现、跨服性能分析面板、官方美术模板和独立业务附属。任何候选都必须先用同一负载证明收益，并保留功能正确且没有严重基础性能问题的开放实现。不会通过固定延迟、减少必要刷新、移除缓存或限制免费版节点数制造差异。

## 人工验收

1. 完整重启测试服，确认 ProtocolLib 已先加载；执行 `/arcmenu mode mouse` 后打开 `example`，画面应立即正对菜单且完全静止。
2. 向四个方向移动鼠标，确认 `mouse.png` 的方向、灵敏度和边缘夹取；背景与菜单不能抖，服务端玩家位置/朝向不能漂移。
3. 让鼠标箭头尖端停在 backend 矩形四角和边缘，右键并用 `/arcmenu pointer` 对照服务端坐标；必须由人工确认尖端就是服务端读取点。切换到触控模式后，同一位置仍使用右键。
4. 检查 cursor tooltip；切换菜单和 back 后光标/屏幕平面不能跳到玩家隐藏视角。
5. 将隐藏 pitch 移至接近上下极限，确认只发生不可见的单次重置，画面和光标没有大幅跳变。
6. 移动、传送、死亡、切世界和撤销权限均不能关闭运行菜单；传送/重生后的实体重建不能触发 close/open 动作。只有 `/arcmenu close`、菜单 `close` 按钮和退出服务器会退出。
7. 显式关闭后确认位置/朝向恢复，camera 回到玩家，私有实体、会话和 ticker 回落。
8. 分别在低延迟和模拟高延迟下观察 camera、系统准星干扰及与移动/反作弊插件的冲突。
9. 在1×1 或相当的狭小空间分别打开触控模式和鼠标模式，确认屏幕的真实尺寸接近 CRServer，且两种模式显示大小与命中位置一致。
10. 按性能矩阵采样至少一组 20/100/300 节点数据；没有真实 bytes/MSPT/FPS 的项目保持“未测”。

鼠标模式经人工确认之前，M6 只能标为候选。被否决的旧 M3 界面已删除并由新的四窗口编辑器候选替代，两者分别验收。
