# M4 资源与模板

M4 当前交付资源构建、图片渲染、CraftEngine 合包桥、CE 物品模型以及组模板底层。被否决的旧 Fabric 界面已由新 M3 编辑器替代；服务器图片候选和组模板拖放现已接入可视化工作区。

## 图片目录与配置

把 PNG 放入 `plugins/ArcMenu/images/` 或其子目录。文件名和目录只能使用小写字母、数字、下划线、点、连字符；菜单填写以 `/` 开头的虚拟路径：

```yaml
frontend:
  logo:
    type: image
    source: /ui/logo.png
    width: 64
    height: 32
    opacity: 255
    offset: {x: 0, y: 20, z: 1}
```

`width`、`height` 可以省略，此时一个 PNG 像素对应一个菜单逻辑单位。只填写一项时另一项仍使用图片固有像素值，不自动锁定比例。规范字段是 `source`；`path`、`image`、`material` 作为输入兼容名，但四者只能出现一个。

路径可以含 PlaceholderAPI 表达式，例如 `/rank/%vault_rank%.png`，所有可能结果对应的 PNG 都必须已存在。配置 `update: 20` 后每 20 tick 检查一次解析结果，值不变时不更新实体。

执行：

```text
/arcmenu reload all
/ce reload all
```

第一条生成：

- `generated/resourcepack/`：展开内容；
- `generated/arcmenu-resourcepack.zip`：交给 CE 的外部资源包；
- `generated/images.index`：稳定的图片到私用码位映射。

不要把图片写进 `minecraft:default`。ArcMenu 只生成 `arcmenu:images`，聊天中输入私用字符也不会自动获得该字体。热构建不能删除已经发布的图片；先移除菜单引用，再完整重启生成不含旧图片的资源包，避免在线实体突然指向缺失字形。

CraftEngine 存在时，ArcMenu 在 `AsyncResourcePackCacheEvent` 中注册 ZIP，CE 负责最终合并和发送。ArcMenu 不再发送第二份资源包。没有 CE 时 ZIP 仍可独立导出，但当前不内置 HTTP 托管。

## CraftEngine 物品模型

`item.material` 先查原版 Material，查不到时以原值查询 CraftEngine：

```yaml
frontend:
  ce-model:
    type: item
    material: mypack:bronze_sword
    context: GUI
    offset: {x: 60, y: 0, z: 2}
    scale: {x: 32, y: 32}
```

可用 context 与原版 ItemDisplay 一致，包括 `GUI`、`HEAD`、`FIXED`、左右手第一/第三人称等。当前是模型展示能力，不等于完整盔甲试穿。ArcMenu 只接 CraftEngine，不增加 ItemsAdder 适配。

仓库中的 `examples/menus/ce-showcase.yml` 使用 toolserver 的 CE 默认资源
`default:topaz_sword` 做真实探针：`FIXED` 展示物品模型，`GUI` 展示同一
ItemStack 的物品栏外观。第三栏将 CE 的 `topaz_background.png` 与
`topaz_frame.png` 作为 ArcMenu 图片按原始正方形比例叠加，用来确认两张
精灵确实进入合并资源包。该菜单依赖本机 CE 包及复制到 `images/ce/` 的
精灵，因此不会随 JAR 自动分发，避免其他服务器因缺少资源而无法加载菜单。

CE 的 `tooltip_style` 是物品数据组件。客户端只会在原版容器为物品绘制
tooltip 时直接使用它，ItemDisplay 本身不会触发原版悬浮层。ArcMenu 因此
提供独立的可选九宫格适配：资源构建时把 background 与 frame 先合成为 9
个切片，运行时根据 Placeholder 展开后的当前文字重新计算宽高。四角保持
原尺寸，只拉伸边和中心；每名正在显示 tooltip 的玩家增加 9 个私有
TextDisplay。没有配置 `skin` 时仍使用原来的单 TextDisplay 纯色背景，不需要
这些图片，也不承担额外实体成本。

`tooltip.yml` 的 `touch`（触控模式）和 `mouse`（鼠标模式）可分别配置；旧文件的
`crosshair` / `cursor` 仍兼容读取。没有 `mouse` 或旧 `cursor` 段时，鼠标模式
完整继承触控模式：

```yaml
touch:
  offset: {x: 10, y: -10, z: 3}
  anchor: bottom-left
  wrap: false
  size: 7
  line-width: 180
  background: '#D0101010'
  skin:
    background: /ce/topaz_background.png
    frame: /ce/topaz_frame.png
    border: 8
    padding: {left: 8, right: 8, top: 8, bottom: 8}
    min-size: {width: 24, height: 24}
    size-adjust: {width: 0, height: 0}
    offset: {x: 0, y: 0, z: -0.25}
    scale: {x: 1.0, y: 1.0}
    text-offset: {x: 0, y: 0, z: 0}
    seam-overlap: {x: 0, y: 0}
    glyph-offset: {x: 0, y: 0}
    column-offset: {left: 0, center: 0, right: 0}
    row-offset: {top: 0, center: 0, bottom: 0}
```

路径相对于 `plugins/ArcMenu/images`。`border` 是原 PNG 的九宫格边宽。`padding`、
`min-size`、`size-adjust`、`seam-overlap`、`glyph-offset`、`column-offset` 和
`row-offset` 均按 tooltip 字体像素填写，会随 `size` 和 `skin.scale` 缩放。
`skin.offset` 与 `text-offset` 的 x/y 是菜单逻辑单位，z 是菜单深度单位。

`anchor` 选择 tooltip 外框中固定落在“指针 + offset”的角；可选
`top-left`、`top-right`、`bottom-left`、`bottom-right`。默认 `wrap: false`
使 tooltip 列表每一项固定为一行；只有 `wrap: true` 时 `line-width` 才触发
客户端自动换行。

正常情况下默认值已经把皮肤包在文字周围。人工微调建议依次进行：用
`skin.offset` 移动整张皮肤；用 `text-offset` 只移动文字；用 `padding` 调四边
留白；用 `size-adjust` 改整体宽高；用 `scale` 修正客户端整体比例；出现细缝时
增加 `seam-overlap`；只有单独一列或一行错位时才用 `column-offset` / `row-offset`；
九块同时存在同方向的细小字形误差时使用 `glyph-offset`。启用或更换皮肤图片、
`border` 后执行 `/arcmenu reload all`，随后执行 `/ce reload all` 让客户端取得新
切片。只改布局参数时普通 `/arcmenu reload` 即可。删掉整个 `skin` 段即可恢复
无资源包 tooltip。

## 组模板

模板放在 `plugins/ArcMenu/templates/*.yml`：

```yaml
schema-version: 1
id: purchase-card
frontend:
  card:
    type: group
    children:
      background:
        type: image
        source: /ui/card.png
        width: 100
        height: 50
      label:
        type: text
        content: '&f购买'
        size: 8
```

一个模板必须只有一个 `type: group` 根节点，不能包含 backend。`/arcmenu templates` 列出已加载模板；`validate` 和 `reload all` 会严格校验整个目录，任一模板错误时保留上一份模板目录。

模板实例化采用副本语义：复制根和所有后代，冲突 ID 自动追加数字，插入后不继续跟随模板变化。新 M3 编辑器支持把组从元素管理器拖入模板窗保存，并把模板卡片拖回元素管理器实例化。

## 当前人工检查

1. 启动后确认日志显示接入 CraftEngine 资源缓存事件。
2. `/arcmenu reload all` 后执行 `/ce reload all`，检查 CE 最终包含 `assets/arcmenu/font/images.json` 和图片纹理。
3. `/arcmenu open m4-resources`，确认 `generated-image` 可见、透明度和宽高正确。已有安装不会覆盖管理员修改过的 `example.yml`，因此使用单独探针菜单。
4. toolserver 可将 `examples/menus/ce-showcase.yml` 复制到菜单目录，打开
   `ce-showcase`，分别检查同一真实 CE 物品的 `GUI` 与 `FIXED` context。
5. 制造损坏 PNG、路径越界或错误模板，确认命令明确失败，现有菜单和上一份 ZIP 仍可用。
