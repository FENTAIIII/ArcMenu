# M3 可视化编辑器

本轮编辑器是被否决的旧 M3 界面的替代实现。它参考 Flashback 的工作区组织方式，但没有复制 Flashback 源码、控件或资源：客户端由 Java 编写，直接使用 Minecraft 26.1.2 与 Fabric API 的 `Screen`、`GuiGraphicsExtractor` 和 `EditBox`。工具图标采用 bbs-mod 的 MIT 授权 16×16 图集，授权文本随模组 JAR 分发；数值 trackpad、多选与右键菜单的行为也参考了 bbs-mod 模型方块编辑器，但编辑状态和网络事务由 ArcMenu 独立实现。

## 工作区

执行 `/arcmenu edit` 后，服务端无视该管理员平时选择的触控模式/鼠标模式策略，专门为编辑会话建立鼠标模式的固定摄像机，并令摄像机正对正式 Display 菜单。切换前端/后端 Tab、提交属性和重建预览时沿用该摄像机；关闭编辑器、退出服务器或会话失效时才恢复玩家视角并删除摄像机。

客户端不会在全屏世界画面上开一个洞。中央可见窗口的宽高始终取同一个整数单位的 `16 × 9` 倍数；相机的投影和剔除宽高使用该 16:9 窗口比例。世界、服务端 Display 和后处理完成后，客户端先复制完整颜色帧，清空主目标，再把**整张真实游戏画面缩放**进中央物理像素矩形，最后才绘制不透明的工具窗口、元素管理器、模板窗口和属性窗口。编辑器禁用 Minecraft `Screen` 默认的全屏半透明暗幕，并在编辑期间隐藏原版 HUD，因此中央窗口不变暗，外侧也不会泄露被裁掉的游戏画面。

四类窗口分别是：

- 左侧**工具窗口**：前端包含选择、组、矩形、边框、线段、文本、图像、物品和方块；后端只包含点击区域。展开图像工具后会列出服务端 `images/` 中的全部候选图片和固有像素尺寸，列表可滚动。
- 右上**元素管理器窗口**：按父子关系显示前端树，后端显示独立的轴对齐区域列表。统一图标按钮展开组、切换 `visible` 和执行只保存在客户端会话中的选择锁定；顶部工具栏提供新建、编组、创建副本与粘贴。
- 底部**模板窗口**：显示服务端 `templates/` 目录中的模板卡片。把元素管理器中的组拖入该窗口可命名并保存模板；把模板卡片拖回元素管理器可实例化副本。
- 右下**属性窗口**：由服务端按节点类型提供可编辑字段，包含位置、旋转、缩放、尺寸、颜色、文字、图片、物品、方块、tooltip、条件和动作等 YAML 参数。

工具栏、右侧栏和模板栏的分隔线可以拖动；尺寸写入客户端 `config/arcmenu-editor.properties`。缩放窗口后中央游戏窗口仍重新取精确 16:9。游戏窗口内另有一个 16:9 的“虚拟屏幕”用于把客户端选择框、命中和拖拽坐标对齐服务端真实 Display；它不改变真实游戏画面的范围。

模组第一次打开编辑器时会写出以下本地校准项：

```properties
virtual-screen-scale=1.0
virtual-screen-offset-x=0.0
virtual-screen-offset-y=0.0
```

`scale` 是虚拟屏幕相对中央游戏窗口的统一比例；发行默认值 `1.0` 覆盖完整 16:9 游戏窗口。offset 使用 GUI 逻辑像素，X 正值向右、Y 正值向上。修改文件后关闭并重新打开编辑器即可重新读取；紫色矩形和左上角数值显示当前虚拟屏幕边界。所有节点框、鼠标命中、拖动和缩放都使用同一校准矩形。

## 服务端权威编辑

客户端不直接读写服务器文件。每次操作都携带当前修订号，服务端重新计算画布坐标、解析完整 YAML、执行正式渲染校验，然后返回 ACK；拖动结束及其他完整事务再返回权威快照。修订冲突、无效数值、未知材质、路径错误或外部文件变化都会拒绝操作，客户端不会把本地猜测视为保存结果。

同一个菜单同一时刻只允许一个管理员写入。编辑预览使用正式 Display 渲染路径和鼠标模式固定摄像机，但不会生成运行菜单的假鼠标实体，也不会执行菜单 actions；可见指针是 Fabric `Screen` 的系统鼠标。前端与后端是两个独立 Tab：切换 Tab 会清除选择，前端组、旋转与缩放不会改变后端点击区域；后端不允许分组并始终与画布横竖轴对齐。

## 编辑操作

选中前端组后使用工具，新元素会成为该组的子节点；否则创建在前端根。后端工具只能创建点击区域。画布中的节点框可以直接拖动；当前选中框右下角的手柄可以缩放前端元素或改变后端交互区域宽高。前端缩放写入节点自己的 `scale.x/y`，并根据父组旋转把屏幕轴尺寸换算回节点局部轴。客户端以最多 20 次/秒且同时只有一个待确认请求的方式发送拖动采样；服务端每次接受采样后都原地更新已生成的真实 Display，不销毁重建菜单。客户端矩形只承担选中框和缩放手柄，不再代替元素运动。中途响应使用紧凑 ACK，松开时提交最终位置并取得完整快照；同一手势的所有采样在服务端合并为一个撤销步骤。元素树中的锁定只防止当前客户端从画布误拖该节点，不写入 YAML。

数值属性框平时可横向拖动，单击后进入精确文本输入；`Alt` 使用精细步进，`Shift` 加速，`Ctrl` 使用大步进。拖动采样沿用最多 20 次/秒和单请求在途限制，并在服务端合并成一个撤销事务。普通文本框按 `Enter` 提交，按 `Esc` 放弃当前输入；boolean 单击切换，choice 单击循环、`Shift` 单击反向循环。`tooltip`、`actions` 和 `deny` 在单行编辑框中用 `\n` 表示换行；actions/deny 的内容按 YAML 片段解析。所有字段仍经过菜单解析器和渲染器验证。

元素管理器支持普通左键单选、`Ctrl+左键` 增减选择、`Shift+左键` 按当前可见顺序范围选择，以及右键上下文菜单。选择项可复制、在原层级粘贴、创建副本、编组、重命名和批量删除；把选择项拖到同一父级的另一行可调整 YAML 顺序。跨组拖动会改变局部变换且某些非等比缩放组合无法无损分解，所以当前会明确拒绝跨组拖动；复制项仍可通过“粘贴到组内”进入目标组。

把组拖入模板窗口后输入模板 ID 并按 `Enter`。模板文件名重复时会拒绝覆盖。把模板拖回元素管理器会复制整个树；若组或后代 ID 已存在，服务端依次追加 `2`、`3` 等数字，保证 YAML 键唯一。右键模板卡片可从服务端 `templates/` 删除该模板；目录刷新失败时会恢复原文件。模板副本不会继续跟随原模板变化。

快捷键：

- `Ctrl+Z`：撤销；`Ctrl+Shift+Z` 或 `Ctrl+Y`：重做；
- `Ctrl+S`：保存草稿到菜单文件；
- `Ctrl+A`：全选当前 Tab；`Ctrl+C`：复制选择；`Ctrl+V`：在原层级创建副本；
- `Ctrl+Shift+V`：把副本放入当前选中的组；`Ctrl+D`：直接创建副本；`Ctrl+G`：把同层选择项编组；
- `F2`：编辑主选择项键名；`Delete`：批量删除选择；
- `Esc`：关闭编辑器并丢弃尚未保存的服务端草稿。

“保存”只原子写入菜单文件，不替换当前运行目录；“应用”先保存，再把整套菜单和动画一起校验，通过后才发布给新会话。检测到磁盘文件被其他程序修改时，两者都会拒绝覆盖。

首次真正写盘时，编辑器在菜单旁创建一次性 `<原文件名>.arcmenu-backup`。拖动画布位置使用文本标量补丁，可以保留原注释与多数排版；创建、删除、模板实例化或一般属性编辑会按 YAML 语义重新输出文档，因此排版、引号风格、锚点和注释可能改变。备份不会在之后保存时被覆盖。

## 构建和安装

服务端仍使用 Maven/JDK 21 或 25：

```powershell
mvn -B -ntp clean verify
```

管理员客户端使用 JDK 25：

```powershell
cd ..\Arcmenu-editor
.\gradlew.bat clean build
```

把 `paper/target/ArcMenu-0.1.0-SNAPSHOT.jar` 安装到服务端，并从 [ArcMenu Editor](https://github.com/FENTAIIII/ArcMenu-Editor) 源码构建 `build/libs/ArcMenu-Editor-0.1.0-SNAPSHOT.jar`；管理员的 Minecraft 26.1.2 客户端还需要 Fabric Loader 0.18.6 与 Fabric API 0.155.2+26.1.2。普通玩家不安装编辑器。

管理员彻底重新连接服务器后执行：

```text
/arcmenu edit example
```

插件消息通道在登录时协商；只执行插件 reload 不能让已经在线且未加载模组的客户端获得编辑通道。

## 当前候选边界

模板卡片当前显示名称、根节点和元素数，不生成最终游戏画面的缩略图。boolean 已提供直接切换，choice 已提供双向循环；color 仍使用文本框并由服务端校验，尚无取色器。前端绘制全部选择项的轴对齐编辑包围框；后端绘制全部点击区域包围框。中央窗口中的元素本体始终是服务端正式 Display，并保留真实旋转。

本轮只构建 Minecraft 26.1.2 客户端。服务端插件的跨版本编译矩阵不代表该模组可以跨 Minecraft 版本直接使用。
